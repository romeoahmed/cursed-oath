# 表现与制作

用轮廓、运动和时序传达招式的方向、重量与规模，保持第一人称操作和战场可读性。伤害与范围见[战斗规格](combat.zh-CN.md)，提交方式与预算见[技术架构](architecture.zh-CN.md)。

## 苍、赫与茈

美术以[概念图](../art/references/limitless.png)为方向：凝实、连续的球形主体承载体积，分块色阶表现能量表面，少量贴面流带和尾迹表达运动。图像是 AI 生成参考；角色细节、环境照明不代表实机功能，也不作为原作证据。

| 能力 | 当前表现                                                                                        |
| ---- | ----------------------------------------------------------------------------------------------- |
| 苍   | 青白主体与深蓝内收流带；手前凝聚后发射，接触后停留，附近方块提供原生碎屑粒子                    |
| 赫   | 紧凑白热中心、赤红边缘和短促放射线；飞行后在命中处展开衰减压力锋                                |
| 茈   | 等大蓝红双球沿水平线靠拢；准备进度 65% 时接触，六 tick 内交融为紫色，随后凝聚、推出并沿路径前进 |

茈的手臂合拢、左手收回与右手推出对应准备和释放阶段。球体从准备阶段的前方位置直接发射，不向视点回拉。苍由准备结束的半径连续扩张；茈随实际可见位移扩张，可见前移 16 格后达到六格半径，服务端从释放起按六格判定。网络插值停留时不提前膨胀。第一人称从手前位置交接，避免前进中的施术者追入延迟的生成画面；第三人称保留原生实体轨迹。三种术式的表面相位和光晕强度在释放时保持连续，茈结束时不追加爆炸。

主体使用原版顶点色并写入深度；光晕、流带和压力锋采用加色混合。细节固定在球面上，按同步年龄运动。保持明亮体积和像素色块，避免塑料高光、独立透明外壳、固定十字几何或松散粒子主体。苍、赫、茈不使用专用着色器。

## 斩击与领域

解以两端收尖的黑色弧刃、窄亮边和短淡尾迹表现；捌在成功接触处展开同样配色的网格，与判定共用跨度、间距，挥空不显示成功网格。黑闪使用黑色分叉斩纹、绯红外沿与命中音，独立于捌和施法动作。

### 无量空处

黑色核心周围的蓝灰、暖白云气弯折且明暗不对称，星尘疏密有别，大块暗部保留深度。亮光融入云缘，不另画发光圆框。这是仿黑洞绘景，不模拟天体物理。

成立后的 24 tick 内，暖白背景短暂显现并沉入暗紫，分簇的紫白线束以错落长度和纵深掠过；线束收束退场时，全景平滑显现。线束两端淡出、细亮芯配弱紫边，避免均匀辐条和持续遮挡。这是视觉过渡，不延迟控制和伤害。过渡使用原版顶点色几何，全景使用原版纹理着色器与顶点色淡入，以相机为中心平移，保持施术朝向；外部球壳固定于领域中心。内部地形不可见，但原世界碰撞保留。纹理、接缝与球面映射的制作要求见[环境说明](../art/README.md#unlimited-void)。

### 伏魔御厨子

神龛在展开位置后方升起。四面巨口的上下颚突出，上腭内凹，前后破风各有一张小口；宽阔挑檐通过檐底、梁架和柱头承托连接。瓦垄、脊端兽骨与基底牛骨保持清晰层次。尺寸、材质和导出约束集中在[模型说明](../art/shrine/README.md)。

斩线固定于领域局部网格，错峰扫开、收尖和衰减，少量长线形成重音。线段最近点距镜头三格内时隐藏，三至七格淡入；按线段中心距离在二十四至三十二格间淡出；摄影机跨格时斩线不整体跳位。黑色主体配窄亮边，重叠领域抑制必中处不生成装饰斩线。范围内使用原生雾呈现淡血红空气，靠近球形边界逐渐恢复，不绘制地面边界环。

简易领域以贴地细白线提示三格保护半径，受侵蚀后出现分散缺口和翘起的边缘；展延以沿身体流动的淡灰流带表现贴身气层，第一人称不遮住自身视点。相交领域的接面显示断续的暗纹与冷暖窄边；完全包含时沿小领域截面呈现压力线。多个无量空处重叠时只提交一个内部全景，避免背景争抢。领域起止、保护破裂和斩击复用原版声音，提供三语字幕；领域内斩击音每五 tick 最多触发一次。

## HUD 与术式轮盘

HUD 在练习能力开放时显示当前术式、可用咒力和预留量；准备、恢复、近战预备、防御、信息过载与熔断只在有效时显示，轮盘打开时隐藏 HUD。

八个生得术式位置固定，自疗、简易领域和展延置于下方。槽位使用短名称，预览区显示全称、可用咒力与消耗；维持型能力显示持续消耗，已开启防御显示解除。咒力不足、信息过载、展延和熔断提示来自同步状态；预览不涵盖全部拒绝条件，施放资格仍由服务端复核。

方向选择保留中心安全区；原生按钮提供 Tab、回车和朗读支持。左键选择，右键或施放键使用，Esc 或轮盘键关闭。白色小方点标记已选术式，彩色边框与方向标记显示当前预览。世界持续运行。操作入口见 [README](../README.md#controls)，文本规范见[三语指南](localization.zh-CN.md)。

## 制作约束

- **时序：**显示使用服务端 tick 与插值；帧率不改变伤害。迟到事件进入当前阶段，不补播过期峰值。
- **空间：**视觉、声音与判定共用中心、方向和时序；通路是否可走以实际方块为准。视觉半径过渡等差异须明确记录。
- **模型：**先确认比例、轮廓与姿态，再加材质和细节。Blockbench 编辑方块模型；需要复杂网格或烘焙时再使用 Blender。
- **动作：**PAL 复用玩家骨骼、皮肤和装备；动画位于 `assets/cursed-oath/player_animations/`，ID 取动画内名称。准备和释放分开播放，不驱动伤害或位移。
- **渲染：**复用 Minecraft/Fabric 管线，缓存几何并按材质分批，裁剪范围包含尾迹。改 shader 前核对目标版本绑定、编译与透明处理。
- **粒子：**优先原生系统。苍的碎屑每客户端最多处理八个场、每场每 tick 两次取样，降低粒子设置时关闭。
- **声音与舒适度：**限制同类并发；“隐藏闪电闪光”减少御厨子斩线候选并降低亮度，同时减弱无量空处展开过渡与领域对抗亮度，不改变伤害。当前没有镜头震动或命中停顿。

PAL 第一人称动作需检查普通/纤细皮肤、持物、双持、护甲、FOV、潜行和游泳。增加局部折射、GPU 粒子或镜头反馈前，先证明可读性收益及性能余量。

制作参考：[Blockbench](https://www.blockbench.net/wiki/guides/blockbench-overview-tips/)、[PAL 播放控制](https://docs.zigythebird.com/pal/gettingstarted/how_to_play_animations/)、[PAL 第一人称](https://docs.zigythebird.com/pal/features/first_person/)、[固定时间步](https://gafferongames.com/post/fix_your_timestep/)、[快照插值](https://gafferongames.com/post/snapshot_interpolation/)。

## 地形表现

真实方块变化承载破坏，短寿命碎屑补足重量：解/捌形成窄切面，茈形成连续通道，御厨子从中心向外粉碎。破坏永久保留，练习使用可丢弃世界。

茈飞行、御厨子必中分别独立于地形处理速度。保护块、掉落和区块卸载规则见[战斗规格](combat.zh-CN.md#术式与地形)。红石、流体、光照与区块重建都纳入性能测量；不使用视觉方块替代破坏，也不自动回填。

## 验收与性能

自动测试验证输入、生命周期、三语界面和效果出现/消失，并覆盖静止、移动施法的准备至飞行交接及插值帧；美术质量必须检查实机截图。皮肤装备、设备组合与多人压力仍需单独验收，不能从单机测试推定通过。

1. 记录 CPU/GPU、分辨率、视距、后端、JVM 和 Mod 列表，测量同场景原版基线。
2. 使用四名玩家、32 个战斗实体、两个交互领域；预热后连续施法和破坏十分钟，保持可重复地形和实体数量。
3. 记录帧时及 tick 耗时的 p50/p95/p99、最大卡顿、分配/GC、队列等待、网络流量与退出残留。
4. 用 JFR 检查服务端与分配；分别测客户端 CPU 提取、GPU 绘制和透明覆盖。`cursed_oath.Terrain` 记录调度耗时、访问、直接移除及剩余工作数。

客户端 60 FPS、服务端 20 TPS 是整局目标，16.7 ms/帧与 50 ms/tick 不由本 Mod 独占。四发茈、32 目标的服务端夹具只验证队列排空；共享 CI 耗时不作为性能验收标准。超预算先减少装饰，保留攻击主体、边界和关键反馈，并用同一基线复测。
