# 动画、特效与地形

表现需传达招式的方向、重量和规模，并保持第一人称操作与战场可读性。当前玩法参数见[战斗规格](combat.zh-CN.md#当前原型)，渲染及破坏实现见[技术架构](architecture.zh-CN.md)。

## 现有表现

| 能力    | 当前形态                                                                                     |
| ------- | -------------------------------------------------------------------------------------------- |
| 苍      | 手前凝聚后发射；暗核、收缩光环和向心轨迹跟随核心，接触后停留；从周围方块取样生成原生碎屑粒子 |
| 赫      | 凝聚、飞行核心与接触爆发分开，保留入射方向；发射和命中各有声音                               |
| 茈      | 准备前 65% 让蓝红核心会合，重合后形成紫色；飞行主体与六格伤害半径对应，带深色核、外壳和尾迹；结束时不额外爆炸 |
| 解 / 捌 | 解使用跟踪弹体的薄刃与短手势；捌在接触处展开网格，与判定共享跨度和间距，挥空不生成网格       |
| 黑闪    | 独立绯红丝带与命中音，不触发捌动作或打断施法动画                                             |

各术式有独立准备/释放动作。方块手只能近似表达手势；精细手指、黑闪黑色内核与扭曲、自定义声音、全部装备组合及其他渲染后端仍待制作或验证。下文为制作规范与后续目标。

## 设计原则

| 原则               | 做法                                                              |
| ------------------ | ----------------------------------------------------------------- |
| 固定模拟、连续显示 | 服务端保持 20 TPS，显示插值；高速攻击扫掠判定，帧率不改变伤害频率 |
| 动作可读           | 蓄势提示承诺，主体提示方向，接触反馈确认结果，余波表达规模        |
| 信息层级           | 优先危险边界和攻击主体，再分配装饰对比度与透明覆盖                |
| 空间一致           | 画面、声音与判定同源；可通行缺口只来自已提交的方块修改            |
| 分层与预算         | 上下身动作分层；按距离、屏幕占比及重要性控制效果数量和寿命        |

时间与显示分离参考 [Fix Your Timestep](https://gafferongames.com/post/fix_your_timestep/) 和 [Snapshot Interpolation](https://gafferongames.com/post/snapshot_interpolation/)；预算、裁剪与复用参考 [Niagara 最佳实践](https://dev.epicgames.com/documentation/en-us/unreal-engine/scalability-and-best-practices-for-niagara)。采用设计原则，运行实现仍使用 Minecraft/Fabric。

## 模型与动作

Blockbench 负责方块角色、低面数建筑和动作；复杂网格或烘焙需要时使用 Blender。引入编辑源时放入 `art/`，导出资源放入 `src/main/resources/assets/cursed-oath/`，记录单位、朝向、枢轴、贴图尺寸和导出工具版本。[Blockbench 指南](https://www.blockbench.net/wiki/guides/blockbench-overview-tips/)

复用玩家骨骼、皮肤和装备。先用手臂、手掌轮廓表达手印，确需附加手指或配件时增加局部骨骼。御厨子建筑以静态低面数主体为基础，仅为运动部分增加骨骼；复杂咒灵另评估专用动画库。

PAL 动画位于 `assets/cursed-oath/player_animations/`，ID 取自动画内名称。移动、施法和受击明确优先级与淡入淡出。第一人称使用第三人称模型部件，需验证普通/纤细皮肤、持物、双持、护甲、FOV、潜行及游泳；需要时另做第一人称姿态，沿用服务端动作时序。[PAL 动作控制](https://docs.zigythebird.com/pal/gettingstarted/how_to_play_animations/)、[第一人称说明](https://docs.zigythebird.com/pal/features/first_person/)

动画帧事件只产生装饰。扣费、命中和结界成立由服务端确认；每个声音或爆发只设一个触发来源。迟到事件跳到当前阶段，过期峰值不补播；动画不推动实体。

## 特效与声音

制作顺序为轮廓和关键姿态、色彩与材质、次级粒子、声音、可选扭曲。每个效果定义中心、方向、寿命和包围体；短瞬效果也需在低帧率下读出结果。

| 能力       | 完整表现目标                                                   |
| ---------- | -------------------------------------------------------------- |
| 黑闪       | 黑红分叉丝带、短促收缩与重击瞬态；确认命中后播放峰值           |
| 苍         | 核心、向心轨道与压缩环，辅以内收颗粒、局部折射和渐变音色       |
| 赫         | 紧致核心、定向扩张环与冲击前缘，外抛碎屑和空气撕裂音           |
| 茈         | 蓝红融合、紫色主体及尾迹，路径冲击和延迟尘带；核心保持周围视野 |
| 解 / 捌    | 薄切面、短暂斩线、断面裂口及定位音效                           |
| 灶         | 热核、射出形态、爆发轮廓，分层火焰与低频尘云                   |
| 无量空处   | 入域转换、内部空间层次与环境声收束；保留控制状态和可交互对象   |
| 伏魔御厨子 | 建筑、范围提示与分布式斩线；碎屑跟随实际破坏批次               |

苍赫融合与黑闪扭曲的演出依据见[集英社导演访谈](https://www.bungei.shueisha.co.jp/interview/jujutsutaidan1/)。具体网格、纹理、声音和时序自行制作，复用环、球、丝带及切面几何。

### 渲染

使用游戏渲染管线和 Fabric 接入点。26.3 的后端、ShaderC 和透明处理需按目标版本验证；自定义 shader 不依赖旧版示例或绕过游戏的后端抽象。[Minecraft 26.3 渲染说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)

基础粒子、声音和低面数网格承担全部必要信息；程序化丝带及材质变化增强招式身份。屏幕扭曲与光晕作为可选层，失败时退回基础表现。

缓存几何与管线，按材质组织批次；提取阶段生成快照，绘制阶段只提交。限制透明覆盖和层数，近镜头装饰淡出，裁剪包围体包含拖尾。退出世界、断线和资源重载需正确释放实例、音源及自有 GPU 资源。

粒子优先复用原生系统，只有必要碎屑参与碰撞。当前苍每客户端最多处理 8 个场、每场每 tick 两次取样；降低粒子设置时关闭碎屑。GPU 粒子只在测量确认瓶颈后评估。

### 镜头与可访问性

命中停顿只影响本地姿态反馈，真实控制效果按玩法处理。镜头震动短、定向且可关闭；强制运镜仅用于主动选择的展示模式。多次爆发合并峰值，限制闪光叠加。

声音分起手、发射、接触和尾音，按距离与重要性限制同类并发。领域进入、保护失效和崩解各有提示。规划字幕、减闪光、震动强度与动态范围选项；危险提示同时依靠轮廓和状态，避免只用颜色或声音传达。

## 地形表现

真实方块变化表达破坏，客户端短寿命碎屑补足重量。保持方块网格；斩击形成窄带切面，茈形成扫掠通道，领域采用持续分区破坏。生存建筑不自动回填，训练场使用可重置场地。

计划和提交都受预算限制。茈队列保存有限短段的几何游标，切割队列保留深度排序候选。提交时读取当前方块、检查材质和保护、调用原生破坏及事件；方块实体、边界与不可破坏块保留。普通破坏生成正常掉落，茈明确粉碎无掉落；不能在预算不足时静默删去已应得物品。

解以前方已处理路径为推进上限；茈的飞行与挖掘独立，已提交短段按预算继续完成。其他工作超时结束未提交部分；领域的实体必中与地形批次分别处理。红石、流体、光照和区块重建纳入性能测量。具体队列算法和限额见[命中与地形](architecture.zh-CN.md#命中与地形)。

后续可加入有限破坏、专用战场和纯视觉模式。模式不关闭世界保护；纯视觉不改变普通攻击遮挡，领域必中仍走自己的规则。

## 验收与性能

先记录 CPU/GPU、分辨率、视距、渲染后端、JVM 和 Mod 列表，测相同场景的原版基线。客户端 60 FPS、服务端 20 TPS 是整局目标；16.7 ms/帧与 50 ms/tick 不由本 Mod 独占。

压力场景目标为 4 名玩家、32 个战斗实体、2 个交互领域，预热后连续施法与破坏 10 分钟。维持实体数量和可重复地形，另做真实战斗体验测试。领域未实现前测已有能力，不能据此宣称完整压力场景通过。

记录帧时及 tick 耗时的 p50/p95/p99、最大卡顿、分配/GC、队列等待、网络流量和退出后的残留。用 JFR 检查服务端及分配，客户端分别测 CPU 提取、GPU 绘制与透明覆盖；根据参考机基线确定阈值后再判断通过与否。

JFR 的 `cursed_oath.Terrain` 事件记录每次地形调度的耗时、访问数、直接移除数与剩余任务数。服务端并发夹具覆盖四发茈、32 个目标与密集地形，验证队列最终排空；它不是十分钟多人性能验收，也不以共享 CI 的耗时作为通过阈值。

退化顺序为装饰粒子、碎屑、烟雾层、后处理，保留攻击轮廓和边界。规则容量不足时明确拒绝新请求。视觉验收覆盖三语、皮肤、装备、画质和可用后端；自动截图用于复现，人工查看负责画面判断。
